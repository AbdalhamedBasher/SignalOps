The Problem

The Anatomy of an Alarm Storm

One Fiber Cut = 4 Cascading Alarms

A physical fiber break at Site RUH-104 produces four distinct alarms within 120 seconds:

  • BACKHAUL_DOWN (Transport Link Failure)
  • CELL_OUT_OF_SERVICE (Radio Access Down)
  • S1_LINK_FAILURE (Core Control Plane Lost)
  • VOLTE_REG_FAILURE (Voice Registrations Failing)

The Status Quo: Flying Blind

Alarm Fatigue: Handled as 4 separate tickets in disconnected queues.

Static Inventory Blindness: Legacy dashboards report "1,240 subscribers affected" from a hardcoded inventory table—a static guess, not live network telemetry.

Costly False Dispatches: Field crews are rolled out without knowing if subscribers are actually cut off or surviving on backup links.

The Solution

SignalOps AI: Three-Pillar Architecture

1. Deterministic Correlation

Sliding time-window grouping collapses bursts into a single incident.

Severity derived from the worst symptom; idempotent alarm ingestion drops duplicates.

2. Autonomous CAMARA Agent

AI agent autonomously queries CAMARA APIs on Nokia Network as Code.

Verifies real device reachability & congestion rather than guessing from alarms.

3. Human Supervisor Gate

Role-based governance ensures AI never modifies networks autonomously.

Runbook-declared supervisor gates with token-attributed audit logging.

Mandatory Requirement #1

CAMARA APIs on Nokia Network as Code

Device Reachability Status

device-status/device-reachability-status/v1/retrieve

Asks whether devices registered at this site can still be reached over data or SMS.

Finding: Turns a static lookup into verified ground truth. Devices still reachable means the site is surviving.

Congestion Insights

congestion-insights/v0/query

Returns congestion over a time window (Low, Medium, High) with a confidence score.

Finding: An independent second opinion on alarms claiming degradation rather than outage.

Location Verification

location/verify

Confirms whether the dispatched engineer's own handset is inside a 2 km circle around the site. Consent-based, and answers yes/no rather than returning coordinates.

Measured limit: in Simulator mode this answers TRUE for any coordinates on Earth, so we mark it unverified rather than call it proof.

Mandatory Requirement #2

AI Agent as Autonomous Tool Orchestrator

Tools the Agent Invokes, Not Buttons a User Presses

Built with Pydantic AI on Google Gemini (both approved tooling). The agent is given an incident and autonomously formulates its investigation:

2. Congestion Tool

Agent queries CAMARA Congestion to corroborate degradation claims.

3. Runbook Tool

Agent reads matched procedures to cite exact remediation steps.

Enterprise Governance

Role-Gated Approvals & Immutable Audit

Runbook-Declared Safety Gates

Procedures carrying operational hazards (e.g. Never reset equipment blind) declare Requires: supervisor directly in version-controlled markdown.

Live Nokia, Precisely Stated

Nokia Simulator mode — as Nokia and the organisers recommend. The API integration is real; the network data behind it is Nokia's simulation. We do not claim live commercial telemetry.
